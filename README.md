# LiePE: Group-Theoretic Positional Encoding Lab

A compact PyTorch research project built around Jane Street's 2026 article
**["Using group theory to explore the space of positional encodings for attention"](https://blog.janestreet.com/using-group-theory-to-explore-positional-encodings-attention/)**.

The core idea is that if a positional encoding modifies attention through linear,
translation-invariant, compositional, continuous relative-position transforms,
then the allowed encodings are highly constrained. They must be generated by a
one-parameter matrix group:

```math
A(t) = \exp(tB)
```

where $B$ is a generator matrix.

This repository turns that perspective into code. It implements standard
baselines like NoPE, RoPE, exponential decay, damped RoPE, and ALiBi, plus an
experimental Jordan-block encoding and a small learned-generator variant.

## Why this exists

Positional encodings are often introduced as isolated tricks. The Jane Street
article gives a cleaner framing: start from the attention score, impose a few
reasonable structural assumptions, and see what the mathematics permits.

Suppose queries and keys at time $t$ are transformed by linear maps $F(t)$ and
$G(t)$. Then the modified attention score between times $t$ and $s$ is governed
by the matrix

```math
F(t)^\top G(s)
```

If we require:

- linearity,
- translation invariance,
- no-op at zero distance,
- composition consistency,
- continuity,

then the relative-position interaction depends only on the offset
$\tau = t - s$. Writing that interaction as $A(\tau)$, the assumptions force:

```math
A(\tau + \sigma) = A(\tau)A(\sigma), \quad A(0)=I
```

This is exactly the definition of a continuous one-parameter matrix group, so:

```math
A(\tau)=\exp(\tau B)
```

That result is the organizing principle for this project.

## What the theory predicts

The article's main conclusion is not "invent a wild new positional encoding."
It is almost the opposite: under the assumptions above, the space of sensible
encodings is already quite small.

### Diagonalizable generators

If $B$ is diagonalizable, its components reduce to familiar behaviors:

- real eigenvalues give exponential growth or decay,
- purely zero eigenvalues recover NoPE,
- complex-conjugate pairs produce 2D rotations, i.e. RoPE-style behavior,
- combining rotation with negative real part gives damped RoPE.

This is why the README and codebase treat RoPE and decay-style mechanisms as
different faces of the same underlying construction.

### Defective generators

If $B$ is not diagonalizable, Jordan blocks appear. Those introduce polynomial
factors into $A(t)$ in addition to any exponential or oscillatory behavior.

That is the unusual corner of the design space explored here. The point is not
that JordanPE is expected to dominate RoPE on language tasks. The point is that
defective generators are mathematically legal under the framework, underexplored
in practice, and plausibly relevant for sequences with trend, velocity, or other
low-order temporal dynamics.

### Where ALiBi fits

Strictly speaking, ALiBi is not inside the article's narrowest linear
transform-on-queries-and-keys setup, because it adds a bias to the score rather
than changing the inner product through the same linear operator family.

The article's addendum notes that ALiBi can still be represented by augmenting
the state, and in practice it remains an important baseline. This repo includes
it for comparison even though it sits slightly outside the cleanest version of
the derivation.

## Encodings in this repo

### NoPE

No explicit positional encoding. In the group-theoretic view, this is the
degenerate case where the relative transform is always the identity.

### RoPE

Rotary positional embedding. In the group-theoretic view, this comes from
2D rotation blocks induced by complex-conjugate eigenvalue pairs with zero real
part.

### ALiBi

Adds a distance-dependent linear attention bias. Included as a practical baseline
and as a reference point for the article's addendum.

### Exponential decay

Applies distance decay to attention logits. This corresponds to negative real
eigenvalues in 1D components.

### Damped RoPE

Combines RoPE-style rotation with exponential decay. This corresponds to complex
eigenvalues whose real part is negative.

### JordanPE

Experimental encoding using Jordan blocks. This creates polynomial terms in the
relative-position transform rather than only exponential or sinusoidal terms.

Example generator:

```text
B = [[0, 1],
     [0, 0]]
```

Then:

```math
\exp(tB) = \begin{bmatrix}1 & t \\ 0 & 1\end{bmatrix}
```

That means the encoding can express linear-in-time behavior, unlike pure
rotations or pure decay.

The motivating intuition from the article is a simple dynamical system:
position-velocity evolution naturally produces this kind of block structure.

### LearnedLiePE

A small learnable generator matrix $B$, with optional stability regularization.

This is intentionally experimental. It can become unstable if the generator has
eigenvalues with positive real parts, i.e. $\Re(\lambda_i(B)) > 0$ for some
eigenvalue $\lambda_i$.

## Quick smoke test

```bash
# Recommended on laptops/CPUs to avoid oversized thread pools:
export OMP_NUM_THREADS=1
export MKL_NUM_THREADS=1

bash scripts/run_smoke_test.sh
```

This runs a tiny training job on the copy-delay task using RoPE.

## Run tests

```bash
pytest -q
```

Run this separately from the smoke test. The tests verify:

- group property for matrix exponential encodings,
- identity at zero distance,
- attention shape consistency,
- basic model forward pass.

## Train a model

Example: RoPE on copy-delay.

```bash
python experiments/train.py \
  --task copy_delay \
  --encoding rope \
  --steps 300 \
  --seq-len 64 \
  --batch-size 32 \
  --d-model 128 \
  --n-layers 2 \
  --n-heads 4
```

Example: JordanPE on a trend / time-series-style sequence task.

```bash
python experiments/train.py \
  --task timeseries \
  --encoding jordan \
  --steps 500 \
  --seq-len 64 \
  --batch-size 32 \
  --d-model 128 \
  --n-layers 2 \
  --n-heads 4
```

Example: compare long-context extrapolation.

```bash
python experiments/evaluate.py \
  --task copy_delay \
  --encoding rope \
  --train-seq-len 64 \
  --eval-seq-lens 64 128 256 512
```

## Research hypothesis

Diagonalizable generators are sufficient for language-like relative-position tasks, but defective generators may help on temporal tasks with latent velocity, trend, or polynomial dynamics.

That is why the project includes both language-like synthetic tasks and
time-series-like synthetic tasks.

- copy-delay and induction-style tasks probe standard relative-position behavior,
- modular tasks probe structured symbolic dependencies,
- timeseries tasks are the natural place to test whether polynomial temporal
  structure buys anything.

## Important warning

This is a research scaffold, not production transformer infrastructure.

Do not start by trying to train a large language model. That would be expensive
and mostly pointless before validating the inductive bias. Start with controlled
synthetic tasks. If JordanPE does not help there, it probably will not magically
help at scale.

## Recommended experimental order

1. Run tests.
2. Run smoke test.
3. Train RoPE on copy-delay.
4. Train JordanPE on copy-delay.
5. Train both on timeseries.
6. Compare extrapolation at longer sequence lengths.
7. Inspect attention maps.
8. Inspect eigenvalue plots.

## Example interpretation

If RoPE beats JordanPE on copy-delay but JordanPE improves on
timeseries/trend-style forecasting, that supports the idea that Jordan blocks
encode polynomial temporal structure.

If JordanPE loses everywhere, the result is still useful: the unexplored
mathematical corner may be elegant but practically weak under these tasks.

Negative results are not failure. Fake positive results are failure.
